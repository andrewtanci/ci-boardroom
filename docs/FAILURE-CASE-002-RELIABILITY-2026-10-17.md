# CI Failure Case 002 — Reliability Gap
Date: 17 October 2026
Status: candidate, not verified runtime behaviour

Reported issues: reactive assistance, continuity gaps, weak accountability, missed anticipation, slow decisions, inconsistent execution.

Core failure class: SPECIFICATION–EXECUTION GAP. Describing good methods does not prove the system applies them.

Required checks:
- Reconcile new input with existing dated records and corrections before answering.
- Use structured computation for trends; identify missing/conflicting values.
- Detect material deviations and blockers using predefined thresholds, avoiding false alerts.
- Provide measurable actions, owner, review date, and revise/stop conditions when warranted.
- Use existing evidence before conducting unnecessary new research.
- Record prediction, actual action, outcome and confounders; revise rules only after evaluation.
- Use proactive named-expert discovery when materially relevant; do not fabricate expert opinions.
- Return concise decisions rather than process narration.

Acceptance cases: prior-context recall; conflicting daily measurement; adverse trend; measurable intervention; deadline anticipation; simple lookup efficiency; repeatability across sessions; high-stakes escalation; cross-domain transfer.

Metrics: recall accuracy, repeated questions, numeric errors, missed trends, false alarms, intervention completeness, decision latency, user corrections.

This is a proposed regression specification only. It does not establish installed Skill activation, automatic monitoring, or measured improvement. No private personal records included.
